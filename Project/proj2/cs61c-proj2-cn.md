### 背景知识

#### 矩阵存储格式

本项目所有二维矩阵都以一维数组按**行主序（row-major order）**存储。行主序把矩阵某一行中的所有值连续存放，再把所有行向量从最上面一行开始拼接成一个一维数组。另一种**列主序（column-major order）**则把某一列的所有值连续存放，再从最左列开始把所有列向量拼接成一维数组。我们选择行主序，遵循大多数 C/C++ 程序的惯例。

#### 数组步长（stride）

数组的步长指连续两个数组元素起始地址之间的字节数。目前我们接触过的数组都是单位步长（unit stride），即相邻元素之间没有间隔，步长就是 `sizeof(element)`。

本项目中所有步长都以元素大小的倍数给出，而不是字节，因此单位步长就是 `1`。

我们将用步长来引用（行主序存储的）矩阵中的列向量，而无需复制任何元素。由于行元素连续存放，行向量就是单位步长的数组。而要取列向量，就需要跳过当前行的末尾和下一行的开头，才能到达该列的下一个元素——因此步长就是一行中的元素个数。

一个实际例子：有向量 `int *a`，含 3 个元素。

- 若步长为 1，则向量元素为 `*(a)`、`*(a + 1)`、`*(a + 2)`，即 `a[0]`、`a[1]`、`a[2]`。
- 若步长为 4，则元素位于 `*(a)`、`*(a + 4)`、`*(a + 8)`，即 `a[0]`、`a[4]`、`a[8]`。

总结：在 C 代码中，访问步长为 `s` 的向量 `int *a` 的第 `i` 个元素用 `*(a + i * s)`，即 `a[i * s]`。如何把这种内存访问模式翻译成 RISC-V 汇编，留待任务 3 的点积中由你自己完成。

我们使用自定义二进制格式存储矩阵的大小和整数值，同时定义一种纯文本表示，并在 `tools` 目录提供 `convert.py` 脚本在两种格式间转换：

- `python3 convert.py file.bin file.txt --to-ascii`：二进制 → 纯文本
- `python3 convert.py file.txt file.bin --to-binary`：纯文本 → 二进制

注意：纯文本格式方便你获得人类可读的矩阵表示，而二进制格式供你的 RISC-V 汇编代码加载和存储矩阵。

##### 纯文本格式

纯文本文件第一行是两个整数，表示矩阵的行数和列数。之后每一行是矩阵的一行。例如一个 3×3 矩阵的纯文本文件如下：

```
3 3
1 2 3
4 5 6
7 8 9
```

注意：矩阵最后一行之后必须有换行。

##### 二进制格式

二进制文件的前 8 字节是两个 4 字节整数，即矩阵的行数和列数。接下来每 4 字节表示矩阵的一个整数元素，按行主序存放，元素之间没有间隔。元素个数必须等于行数与列数之积。整数以小端序（little-endian）存储，下文详述。

注意：以该格式存储的 M×N 矩阵大小为 `sizeof(int) * (2 + m*n)`。

##### 查看二进制文件

在命令行查看任意二进制文件，推荐 `xxd` 命令。它默认以十六进制输出文件的原始比特。例如，把上一节的纯文本示例存为根目录下的 `file.txt`，运行 `python convert.py file.txt file.bin --to-binary` 转成二进制，再 `xxd file.bin`，应输出：

```
00000000: 0300 0000 0300 0000 0100 0000 0200 0000 ................
00000010: 0300 0000 0400 0000 0500 0000 0600 0000 ................
00000020: 0700 0000 0800 0000 0900 0000 ............
```

按每 4 字节（等价于 8 个十六进制位）、以小端序（见下文）解读这份输出，就能看到它们对应纯文本文件中的值。别忘了前两个 4 字节是表示维度的一对整数，其余是矩阵的整数元素。

请实际尝试上面的例子：生成 `file.txt`、运行 `convert.py`、用 `xxd` 检查结果。

注意：虽然也可以用 `hexdump` 程序检查字节，但字节序（endianness）会有所不同。为简单起见，答疑时间和 signoff 时助教只支持 `xxd`。

注意：简单的 `xxd` 命令在 Venus 网页界面的 shell 中同样可用。

##### 字节序（Endianness）

注意字节按小端序排列：最低有效字节放在最低内存地址。对文件而言，文件开头被视为"较低地址"。这与我们把文件读入内存的方式，以及数组首元素通常位于最低内存地址的事实相关。

RISC-V 默认使用小端序，我们的文件也全都是小端序。一般来说写代码时不必担心字节序；但在调试、检查内存或文件中的字节（如使用 `xxd`）时，必须把它记在心里。

#### 文件操作

本节详细介绍访问文件所用到的辅助函数，实现 `read_matrix` 和 `write_matrix` 时需要用到。

##### `fopen`

打开一个文件，之后可根据我们提供的权限位对其进行读写。返回一个与该文件绑定的唯一整数——文件描述符（file descriptor）。在对文件做任何其他操作之前，必须先调用此函数。

- 参数：
  - `a1`：指向字符串的指针，为要打开文件的文件名。
  - `a2`：整数，表示打开文件所用权限。例如可以只读权限打开，从而禁止写入。本项目中只需关心几个基本权限位：`0` 对应 `r`（只读），`1` 对应 `w`（只写）。注意：`w` 若文件已存在则覆盖，不存在则创建。
- 返回值：
  - `a0`：文件描述符，与该文件绑定的唯一整数。后续读写、关闭等文件相关函数都作用在这个文件描述符上。失败时 `a0` 为 `-1`。

##### `fread`

从文件读取给定数量的字节到缓冲区——一块预分配的、用于存放这些字节的内存。注意，重复读取会读取文件中连续的字节：例如对某文件两次各 `fread` 8 字节，会读入前 8 字节和后 8 字节，而不会两次读到同样的 8 字节。

- 参数：
  - `a1`：要读取文件的描述符，由之前的 `fopen` 返回。
  - `a2`：指向缓冲区的指针，文件字节将被读入这里。调用前必须先分配好大小合适的内存，并以指针传入。
  - `a3`：从文件读取的字节数。
- 返回值：
  - `a0`：实际读取的字节数。若实际读取数与输入指定的数量不符，说明要么到达文件末尾，要么发生了错误。

##### `fwrite`

写入给定数量、给定大小的元素。与 `fread` 一样，对同一文件的后续写入不会重叠，而是依次追加。注意，与 `fread` 不同，我们传入的不是总字节数，而是元素总数和每个元素的字节数；两者相乘即为写入的总字节数。

另外，写入内容直到我们运行 `fclose` 或 `fflush` 才会真正保存。

- 参数：
  - `a1`：要写入文件的描述符，由之前的 `fopen` 返回。
  - `a2`：指向缓冲区的指针，缓冲区中存放要写入文件的内容。
  - `a3`：要从缓冲区写入的元素个数。
  - `a4`：每个缓冲区元素的字节数。
- 返回值：
  - `a0`：实际写入文件的元素个数。若 `a0 != a3`，说明要么到达文件末尾，要么发生了错误。

##### `fclose`

用完文件后将其关闭，保存我们对其做出的所有写入。

- 参数：
  - `a1`：要关闭文件的描述符，由之前的 `fopen` 返回。
- 返回值：
  - `a0`：成功为 0，否则为 -1。

#### 网络结构

（验证命令行参数数量后，）你要做的第一件事是通过多次调用 `read_matrix`，按命令行参数把 `m0`、`m1` 和 `input` 矩阵加载进内存。记住需要传入两个整型指针参数。

接下来，用这三个矩阵计算输入的得分。我们的网络由一次与 `m0` 的矩阵乘法、对结果的 relu、再一次与 `m1` 的矩阵乘法组成。最终将得到每个类别的得分矩阵。然后挑取得分最高的下标，该下标就是输入的分类。

给定两个权重矩阵 `m0`、`m1` 和输入矩阵 `input`，生成各类别得分的伪代码如下：

```
hidden_layer = matmul(m0, input)
relu(hidden_layer)  # 回想：relu 是原地操作
scores = matmul(m1, hidden_layer)
```

得到得分后，要求你把它们保存到命令行传入的输出文件中。然后调用 `argmax`，它会返回一个代表输入分类结果的整数；若 `a2` 的值表示应打印，则将其打印出来。

提示：调用 `argmax` 和 `relu` 时，应把输入当作一维数组——即传入函数的长度应是整个矩阵的元素总数。

A U.2：`-k` 标志是 Python 3.7 才加入的。项目规范中的命令已更新为在旧版 Python 上也能运行的形式。

**Q U.3：如何检查返回码？**
A U.3：可以修改 `AssemblyTest` 类 `execute` 方法的可选参数 `code`。默认期望的 `code` 为 `0`；要检查其他退出码，按 `t.execute(code=78)` 这样使用。

**Q U.4：可以引入 numpy 之类的非标准库吗？**
A U.4：自动评分器只能访问 Python 标准库，`import numpy` 会导致失败。你完全可以新建一个测试文件来试用 numpy，但这些额外测试不会被自动评分器考虑。

**Q U.5：你们测的覆盖率具体指什么？**
A U.5：我们统计的是你的实现（如 `abs.s`）中每条指令在**所有**测试中被执行的次数。单个测试不需要覆盖代码中的全部指令；要拿覆盖率的分数，你的测试需要合力把实现中的每一条指令至少执行一次。简单说：覆盖程序所有分支和不同的执行路径。

**Q U.6：怎么查看自己没覆盖到哪些指令？**
A U.6：在所有测试运行后执行的 `print_coverage` 调用中，把 `verbose` 改为 `True`，它会打印你实现中每一条指令的覆盖情况。

**Q U.7：为什么 Windows 上出现 `argument of type 'WindowsPath' is not iterable` 错误？**
A U.7：Windows 上需要 Python 3.8（当时最新稳定版）才能运行这些单元测试；也可以使用 WSL，它对较旧的 Python 3 版本也可用。

**Q U.8：可以修改某些测试的参数吗？**
A U.8：随意修改我们提供的代码，唯一要求是 TestCase 类的名字保持不变——自动评分器在测量覆盖率时把这些名字写死了。

**Q U.9：为什么出现 `ImportError: Failed to import test module: TestAbs` 错误？**
A U.9：你必须从 `unittests` 目录运行单元测试！

### A 部分

#### ReLU 与 ArgMax

**Q X.1：怎么用错误码退出（终止）程序？**
A X.1：看一看我们在 `utils.s` 中提供的 `exit2` 函数。

**Q X.2：要把 `utils.s` 里的函数复制到自己的代码里吗？**
A X.2：**绝不**要从 utils.s 复制函数！编写单元测试时 `utils.s` 会被自动导入。在 Venus 中调试时，请确保运行的是单元测试（位于 `unittests/assembly`），而不是直接运行 `relu.s`，例如 `vdb unittests/assembly/TestRelu_test_simple.s`。入门视频里有演示。

**Q X.3：为什么出现 `could not find label exit2` 或 `label exit2 used but not defined` 错误？**
A X.3：绝不应该在 Venus 中直接运行 `relu.s`；应运行单元测试，例如 `vdb unittests/assembly/TestRelu_test_simple.s`。

**Q X.4：一维向量是什么意思？**
A X.4：relu 函数把矩阵当作连续向量处理，例如 `3x2` 矩阵会被当作大小为 `6` 的向量。

**Q X.5：总是要填写 epilogue 和 prologue 吗？**
A X.5：你必须始终遵守调用约定！有时这不需要额外代码，此时 epilogue 或 prologue 可以为空。

#### 点积（Dot Product）

**Q D.1：如何验证向量长度参数与实际分配的内存大小相符？或者说，如何验证为向量分配了足够的内存？**
A D.1：和 C 一样，函数无法验证向量长度参数与实际分配内存大小是否相符。

**Q D.2：可以添加额外的标签（label）吗？**
A D.2：可以，只要别把它们设为全局（`.globl`）。

**Q D.3：自动评分器会不会像 lab04 的评分器那样，通过修改寄存器来测试调用约定？**
A D.3：自动评分器调用函数时可能修改一些寄存器（但只修改它允许覆盖的那些）。请确保遵守调用约定——调用你自己的函数（如 `matmul` 调 `dot`）时也一样！

#### Matmul

**Q M.1：能否假定 `a6` 指向的内存区域有足够空间存放结果？**
A M.2（原文如此）：`a6` 指向的内存区域有足够空间容纳结果 `d` 的全部值。`matmul` 函数本身不必调用 `malloc` 为结果分配空间。

**Q M.3：能否假定参数给定的维度与数组元素个数相符？若不能，如何检查数组长度？**
A M.3：和 C 一样，函数无法验证矩阵大小参数与实际分配内存大小是否相符。

**Q M.4：`matmul` 只需要支持方阵吗？**
A M.4：矩阵不必须是方阵。检查 `m0` 和 `m1` 的维度是否匹配，是必须做的三项错误检查之一（`matmul.s` 的描述中列出了所有需要执行的检查）。

**Q M.5：能否假定 `d` 有特定的初始值？**
A M.5：不能。假定 `d` 分配了足够内存，但其中的值未初始化。

**Q M.6：可以在 Prologue 之前检查非法参数吗？**
A M.6：可以，只要不违反调用约定。

**Q M.7：可以把 `t` 寄存器的值存到栈上、调用函数后再恢复吗？**
A M.7：可以。调用约定的全部含义是：调用函数后 `t` 寄存器可能含任意值。注意正确地递减/递增栈指针即可。

**Q M.8：`m0` 和 `m1` 的维度"make sense"（合理）是什么意思？**
A M.8：行数和列数都大于等于 1。

**Q M.9：如果 `m0` 和 `m1` 的维度都不合理，应该用退出码 72 还是 73？**
A M.9：需要按头注释中列出的顺序从上到下检查错误。

### B 部分

#### 读取矩阵（Read Matrix）

**Q R.1：怎么判断 `malloc` 是否失败？**
A R.1：返回的地址会是 `0`。

**Q R.2：怎么判断 `fopen` 是否失败？**
A R.2：请阅读项目规范中关于 `fopen` 的小节。

**Q R.3：什么时候应该用退出码 `1`？**
A R.3：**永远不要**用退出码 `1`。我们有一些旧指引没来得及删除（现已修正）。本学期所有错误码都是两位数（十进制）。

**Q R.4：我的某些 `.data` 没有按 4 字节对齐，为什么？**
A R.4：Venus 链接器不对任何静态数据段做对齐，因此 `.word` 可能开始于任意地址。

**Q R.5：如果矩阵为空，该用什么错误码？**
A R.5：由于没有为此规定错误码，你可以假定读入的所有矩阵维度都是合理的。

**Q R.6：如何测试 `read_matrix` 的输出数组是否正确？**
A R.6：了解 `AssemblyTest` 类的 `check_array_pointer` 方法。

#### 写入矩阵（Write Matrix）

**Q W.1：我们需要调用 `fflush` 吗？**
A W.1：没有必要调用 `fflush`。

**Q W.2：如果 `malloc` 失败应返回什么退出码？**
A W.2：虽然实现本函数不要求使用 `malloc`，但若 malloc 失败，应始终返回退出码 `88`。

**Q W.3：`do_write_matrix` 总是检查输出文件，但我测试错误用例时不会产生文件，怎么办？**
A W.3：你可以随意往 `do_write_matrix` 添加代码，例如在不需要时跳过文件检查。

#### Classify

**Q C.1：可以假定输入矩阵是展平的吗？**
A C.1：MNIST 和 `simple0` 网络的输入是 N 行 1 列的矩阵。可以这样查看示例输入：`cat inputs/simple0/txt/inputs/input0.txt`。但 `simple2` 网络的输入实际多于 1 列，请查阅项目规范，理解如何处理这种情况。

**Q C.2：分类一个 MNIST 输入需要多久？**
A C.2：在一台 5 年前的笔记本（OpenJDK 1.8）上，工作人员解法分类 `mnist_input0.bin` 约需 33 秒，约 120 万条指令。

**Q C.3：如果 `malloc` 失败，之前分配的内存还要释放吗？**
A C.3：不需要。退出前不必释放。

**Q C.4：`TestClassify` 和 `TestMain` 有什么区别？**
A C.4：`TestMain` 与自动评分器运行的健全性检查非常相似；`TestClassify` 是留给你扩展、测试边界情况的。例如 `TestMain` 总是把 `a0` 设为 `0`，而 `TestClassify` 应该测试 `a2` 的另一个取值。

**Q C.5：自动评分器要跑多久？**
A C.5：平均 2–5 分钟。

**Q C.6：如果输出路径中某个目录不存在，我们的代码应该能创建它吗？**
A C.6：不需要。你可以假定输出目录已存在，只有文件本身需要由 `fopen` 创建。
